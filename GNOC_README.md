# 🌍 GNOC - Global Neural Operations Center

## Архитектура системы реального времени

Система представляет собой **центр управления глобальной сетью устройств** с подключенной картой мира, базой данных устройств и роем из 3 нейросетей для коллективного анализа.

│                    GNOC Dashboard (Web UI)                       │

│  │   (Leaflet.js)      │  │   Neural Swarm Control           │  │
│  │   • 8+ узлов        │  │   Real-time Events               │  │
│  │   • Связи           │  │   Analysis Reports               │  │

│  │  WorldMapContext     │    │  NeuralSwarmAnalyzer         │   │

## 🧠 Neural Swarm - Рой из 3 нейросетей

Три специализированные нейросети работают **параллельно** над одной задачей:

### 1. NET-SEC-01 (Security Analyst)
- Проверка уязвимостей
- Анализ протоколов шифрования
- Оценка уровня безопасности

### 2. PERF-02 (Performance Analyst)
- Мониторинг нагрузки
- Оптимизация производительности
- Балансировка ресурсов

### 3. ANOM-03 (Anomaly Detection)
- Поиск нестандартной активности
- Выявление аномалий в трафике
- Обнаружение угроз

### Процесс консенсуса

```
1. Получение данных об узле
         ↓
2. Параллельный анализ (3 сети)
         ↓
3. Сбор результатов
         ↓
4. Выделение согласованных находок
         ↓
5. Определение спорных моментов
         ↓
6. Формирование приоритетных действий
         ↓
7. Итоговый отчет с уровнем угрозы
```

## 📊 Функции реального времени

### Event Bus (Pub/Sub)
- Автоматическое обновление при изменениях
- Подписка на события сети
- История последних 1000 событий

### Асинхронная архитектура
- Неблокирующий GUI
- Параллельный анализ нейросетями
- Фоновая симуляция активности сети

### Единая база знаний
- `WorldMapContext` - центральное хранилище
- Версионирование состояния
- Thread-safe операции с asyncio.Lock

## 🔌 API Endpoints

| Endpoint | Method | Описание |
|----------|--------|----------|
| `/` | GET | Веб-интерфейс GNOC |
| `/api/snapshot` | GET | Текущее состояние карты |
| `/api/analyze/<node_id>` | POST | Запуск анализа нейросетями |

## 🎯 Сценарии использования

### 1. Мониторинг глобальной сети
- Просмотр всех устройств на карте мира
- Отслеживание статуса в реальном времени
- Получение уведомлений об изменениях

### 2. Анализ безопасности узла
- Выбор устройства на карте
- Запуск анализа тремя нейросетями
- Получение консенсус-отчета с рекомендациями

### 3. Оптимизация производительности
- Выявление перегруженных узлов
- Автоматические рекомендации по балансировке
- Интеграция с квантовым оптимизатором

### 4. Обнаружение аномалий
- Непрерывный мониторинг трафика
- Сигнализация о нестандартной активности
- Приоритетные действия для устранения
